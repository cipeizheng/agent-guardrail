# ADR-0014：当前架构基线与增量决策

- 状态：Accepted
- 日期：2026-08-11
- 历史范围：ADR-0001–0013 已移出当前文档树
- 当前合同：[`current-architecture-contract.md`](../current-architecture-contract.md)

## 背景

早期 ADR 同时保存决策、竞品调研、迁移步骤和当时的实现状态。随着实现多次切换，旧记录之间形成复杂的
部分替代关系，日常任务需要加载大量历史文本才能判断当前事实，并出现把 roadmap 序号和 capability
完成状态理解错误的问题。

项目已经拥有可由代码和测试验证的单一生产链。继续让历史迁移记录承担当前规范职责，成本大于收益。

## 决策

1. `docs/current-architecture-contract.md` 是当前生产架构和不可破坏约束的短合同。
2. 运行时路由、环境变量、Schema、默认 capability 和验证状态分别由合同列出的代码/矩阵作为事实来源。
3. ADR-0001–0013 移出当前文档树，不再保留当前规范权、兼容承诺或日常可发现性。
4. 未来 ADR 只记录对当前合同的长期增量或替代；实现状态、调研和执行计划放在专项文档。
5. Capability 使用稳定 ID 和封闭状态；真实后端未运行时只能标记 `adapter_only`，不能标记 `verified`。
6. 文档必须区分当前实现、设计合同和规划；已移出的旧 ADR 不得重新成为现行文档的规范性依据。

## 安全与兼容性

- 本决策不改变运行时代码、Policy Schema、协议或 Enforcement 顺序。
- 当前合同保留现有 fail-closed、显式 provenance、pending 原子性、脱敏和 pre/post 副作用边界。
- 旧版本 Policy 或历史 API 不因移走旧 ADR 而恢复兼容；实际兼容性以当前代码和合同为准。
- 若要降低当前安全约束，必须新增 ADR、更新合同并提供相应安全测试，不能只修改 roadmap。

## 后果

- 日常任务不再加载全部历史 ADR，上下文用于当前代码、专项设计和测试。
- 当前仓库不再用旧 ADR 解释现行行为；代码、合同和专项事实来源足以追溯当前设计。
- 新 ADR 更短、更稳定；频繁变化的 capability 进度由机器可读矩阵管理。
- 维护者必须同步更新当前合同、事实来源和防漂移测试。
